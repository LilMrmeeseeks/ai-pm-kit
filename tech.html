2三条能直接改简历的结论

① 溢价在 Agent，而你正好在 Agent 上

Agent / 智能体这一族条数第二多（23 条）、中位最高（25–50k）。你的四个项目——CAD 审图的规则+检索分工、海图四个子智能体的边界切分、咖啡的检测与大模型双通道、智能体工厂的生成流水线——全部是 Agent 工程问题，不是模型训练问题。

简历第一行不要写「AI 产品经理」，写「智能体产品：多智能体边界切分 / 规则与模型分工 / 上线验收」。

② 通用「AI 应用」量最大，但那是价格洼地

52 条通用岗中位 20–38k，比 Agent 族低一档。这类岗的 JD 通常只写「懂大模型、能提需求、能推动落地」——门槛低、竞争者多。

你要做的不是避开它，而是用同一份经历投两类岗：投通用岗时把项目讲成「落地能力」，投 Agent 岗时把同一段讲成「架构判断」。

③ 评测岗少、贵、且你有一半现成素材

只有 6 条，但中位 25–50k。原因是能定「什么叫做对了」的人稀缺。

你手上有三套现成的验收口径：CAD 的 85/70/85 + 80 张读通 60 + ≤3 分钟 + 连续 3 天；海图的四项考核目标；工厂的三道验证门（静态检查 / 沙箱 60 秒 / 20 例）。这就是评测岗的语言。

④ 经验要求：3–5 年是主战场

22 条要 3–5 年，11 条不限经验，9 条要 5–10 年，8 条要 1–3 年。3–5 年这一档竞争最密，也是「项目讲得清」比「年限够」更起作用的一档。

所以这一页的重点不是补年限，是把四个项目讲到能被追三层。

3这份数据不能证明什么

样本是深圳、单平台、关键词页抓下来的，重复岗位没有去重，薪资取的是页面首屏区间。所以：不要用它算「AI PM 平均年薪」，也不要用它推「哪个方向明年还火」。它只能证明一件事——这 75 份 JD 里，哪些词被写下来了。下一页就是这件事。

覆盖率 = 75 份 JD 正文里，提到该词的岗位占比（一个词在一份 JD 里出现多次只算一次）。 这个排序不是「重要性排序」，是用人部门写在纸面上的期待——它决定你的简历会被哪句话钩住，也决定技术面从哪一层切进来。 用法：先看 Tier 1（≥45%，不答就是硬伤），再扫 Tier 2（25–45%，答得出就拉开差距）。Tier 3/4 是「提到了会加分，没提到别主动展开」。

JD 怎么写
「推动跨部门协作」「对最终交付负责」「协调研发、算法、业务资源」。
怎么问
「研发说做不了，你怎么办？」「排期要延期，你怎么跟客户说？」
你用哪个答
两个真实回合：① 你提「直接并发调模型」，算法同事按调用量估了一遍说成本兜不住，你当场收回，改成批量提取 + 结果缓存，顺带把接口抽了一层，后来换国产模型业务代码没动；② 海图十二个接口分属不同部门、你方推不动，改成客户信息部门牵头，我方只出接口清单和优先级。
别说

API / 工程协作77%58/75 篇
JD 怎么写
「能与研发/算法团队高效沟通」「熟悉 API 设计与联调」「理解技术实现路径」。
怎么问
「你怎么判断研发说的『做不了』是真做不了，还是不想做？」
你用哪个答
拆成三种「做不了」：能力不行（要证据：换一个样本还能不能复现）、代价太高（要分母：多少条数据、多少调用量、多少钱一次）、责任不清（要归属：判错了谁签字）。你在 CAD 项目上遇到的是第三种——钱总工那句「我就担心你们系统说没问题，最后图审退回来，责任算谁的」，直接把技术路线逼成了规则引擎。
别说
别说「我不懂技术，但我懂需求」。这句话在技术负责人面前等于「我不会被追问」。

大模型 / LLM73%55/75 篇
JD 怎么写
「熟悉大模型能力边界」「了解主流模型差异」「能判断什么场景该用大模型」。
怎么问
「什么场景不该用大模型？」——这是产品岗最常用来筛人的一题。
你用哪个答
三句话原则：要可复算的不给它（配筋率计算、工期统计）、要可追责的不给它（判定结论）、要穷举的不给它（8 类 SOP 检测用闭集 YOLO 更便宜更稳）。它该干的活是：把不确定的语义收窄（这句通告是临时作业还是永久变化）、把事件列表翻成人话（「今天先看这三家店」）、把规范条文找出来（带版本号，只引用不生成条号）。
别说
别说「大模型什么都能做，看 prompt 写得好不好」。这句话会让技术面直接开始考你。
Agent / 智能体60%45/75 篇
JD 怎么写
「有 Agent / 智能体产品设计经验」「理解多智能体协作」「设计过工具调用与任务编排」。
怎么问
「你为什么把它拆成四个 Agent，而不是一个大 Agent？」「什么时候不该用 Agent？」
你用哪个答
海图：客户嘴里是「一个 AI 助手」，你拆成四个——A1 负责问、A2 负责派、A3 负责改、A4 负责画。拆的依据不是功能清单，是流水线顺序（整编是输入、编绘是入库、制图是输出）+ 每段有独立的责任人和边界。反例也现成：客户原本那套是单体 Agentic RAG，一条链、一个入口，只能查资料；要它去「真的出一张图」就垮了。
别说
别说「Agent 就是会自动调工具的 chatbot」。这句话把 Agent 说成了产品形态，而它是职责划分。

JD 怎么写
「独立完成需求分析与 PRD」「能把业务需求转成产品方案」。
怎么问
「AI 产品的 PRD 和普通 PRD 差在哪？」
你用哪个答
差在三处必须写死：① 边界（哪些不做——CAD 合同里写了不做 PDF 审图、不做全专业全图、不做三维 BIM、不代替签字）；② 失败态（不确定时输出什么——「疑似违规」这一档，钱总工说这句比「通过」值钱）；③ 验收口径（85/70/85 三条线 + 80 张读通 60 + ≤3 分钟 + 连续 3 天不崩，双签）。普通 PRD 不写这三样，因为普通功能没有「概率」。
别说
别说「PRD 都差不多，加个模型调用说明就行」。

怎么问
「你怎么看 XX 家的方案？为什么不做成他们那样？」
你用哪个答
CAD 那条：否掉「端到端大模型直读图纸」，理由不是模型不行，是合同写着「规则引擎计算逻辑正确，输入正确参数后，计算结果零误差」——概率系统给不了这个承诺。同一逻辑，你在咖啡项目否掉了「端到端 VLM 当主机位」：24×7 连续理解，成本撑不住，而且五类计数根本不需要语义理解。

指标体系48%36/75 篇
怎么问
「这个 AI 功能上线，你看哪几个数？」
你用哪个答
三层，一层不能少：业务层（督导少跑几家店 / 一条通告核对从 2.5 分钟到 40 秒 / 单面墙复核 6 分钟到 1.5 分钟）→ 产品层（采纳率、人工改写率、「疑似」档占比、复核时长）→ 技术层（召回、精确率、P95 延迟、单次成本）。见「成本与指标」一页。
数据分析41%31/75 篇
怎么问
「你怎么证明这个功能有用？」
你用哪个答
反着说：先定义「错在哪」，再谈准确率。CAD 那次 52% 的复合配筋场景，78% 的误判来自「附加筋漏算」——一个可归因的错因，比一个漂亮的总体准确率有用得多。修完 52%→74%、漏算 78%→9%、标准标注 87.5%→88% 无回退。
模型评测36%27/75 篇
怎么问
「你怎么知道它变好了？离线好上线差怎么办？」
你用哪个答
工厂那三道门就是评测：门 1 静态检查（schema 合法 / 工具真的存在 / 权限不越界）→ 门 2 沙箱跑通（独立容器、限时 60 秒、断外网、mock 数据）→ 门 3 20 例。三层分别抓「写错」「跑不起来」「跑得不对」。另外一条硬规矩：口头警告必须当场转成测试用例——CAD 那条复合标注的雷，就是 4 月钱总工口头警告了、5 月没转成用例、11 月炸的。
RAG / 检索增强32%24/75 篇
JD 怎么写
「熟悉 RAG 原理与优化」「有知识库问答落地经验」。
怎么问
「RAG 答不准，你从哪一层查？」——答错这一题的人，通常只会说「换更好的 embedding」。
你用哪个答

别说
别说「RAG 就是把文档丢进向量库」。这是 2023 年的话术。

多模态29%22/75 篇
怎么问
「这个场景用视觉模型，为什么不用 OCR / 不用规则？」
你用哪个答
三次不同的选择，正好是一张决策表：CAD 图纸——文字本来就在矢量层，直接取，OCR 只兜扫描件，VLM 直读被判「文档理解成立、工程图纸空间语义推理不成立」；咖啡门店——8 类 SOP 里五类计数用闭集 YOLO（目标稳定、类别可穷举），有效期用「检测框 + OCR + 日期规则」因为要可复算，只有「现在店里有几个员工」这种没装专项的问题才抽一帧给多模态模型现场看；智能体工厂——不用视觉，用卡片把自然语言选择化。
别说
别说「多模态就是能看图」。判断点是要可复算还是要泛化，可复算就别上大模型。

技术主干八讲

按「被问到的概率 × 你已有的素材」排序，不是按教科书顺序

1 · RAG 全链路 你已有 77 篇语料可查

一句话：把「查得到的资料」在提问那一刻塞进上下文，让模型基于资料回答并给出处。

六个环节：切分 → 向量化 → 召回（可多路）→ 重排 → 拼上下文 → 生成带引用。答不准时按环节定位，不要一句「换个 embedding」。

你要判断的：这问题该用 RAG 还是长上下文？（资料会变、要出处、要控成本 → RAG；一次性读完整份合同 → 长上下文更省事）

他会问RAG 答不准，你从哪一层查？／为什么不用微调？／召回率上不去怎么办？

2 · Agent 与工作流 你的主战场

一句话：工作流是「步骤写死的流水线」，Agent 是「模型自己决定下一步」。前者可测可回放，后者能处理没预料到的输入。

判断线：步骤能穷举 → 工作流；输入形态不可穷举、但每步动作可枚举 → 工作流 + 模型做判断；连动作都要现场想 → Agent。

你的锚：海图四个子智能体不是「四个 chatbot」，是按流水线切的四段职责；CAD 里规则引擎负责确定判定、模型只做语义收窄——这是「Agent 里最贵的那部分被拿掉了」。

他会问什么时候不该用 Agent？／多 Agent 怎么划边界？／它们之间怎么传状态？

3 · 工具调用与 MCP

一句话：模型本身只会输出文字；能「查库、发请求、出图」是因为外面挂了一排工具，模型输出「我要调哪个、参数是什么」。MCP 是把这套挂载标准化的协议。

你要判断的：工具清单要短（每个工具都是一次误调用的机会）、写操作要人确认、失败要有回退话术。

他会问模型把参数填错了怎么办？／工具权限怎么控？

4 · 多模态 三次不同选择

一句话：能看图/听音不等于能判断。判断点是要可复算还是要泛化。

决策表：要可复算 → 专用小模型 / OCR / 规则；要泛化、要处理没见过的问法 → 多模态大模型；两者都要 → 双通道（专用先跑，没覆盖的抽一帧给大模型）。

他会问为什么不用 VLM 直接读图？／分辨率怎么处理？／抽帧策略怎么定？

5 · Prompt 与上下文工程

一句话：不是措辞艺术，是上下文预算管理——这一轮给模型看什么、按什么顺序、留多少给输出。

四件确定的事：结构化输出（schema / JSON，别让模型自由发挥格式）、少样本要挑「边界样本」而不是「典型样本」、长文档先摘要再问答、把「不许做的事」写成硬约束而不是请求。

他会问输出格式老是不稳怎么办？／上下文塞满了怎么取舍？

6 · 评测 你最强的差异点

一句话：评测不是打分，是定义「什么叫做对了」，并让它可重复。

四层：离线集（有标准答案的 N 条）→ 回归集（历史 badcase 常驻）→ 上线门（静态 / 沙箱 / N 例）→ 线上抽检（人工 + 自动判官）。最贵的是回归集，因为它只能靠事故攒。

他会问离线好上线差怎么办？／谁来标？标多少条够？／LLM 当裁判可信吗？

7 · 成本

一句话：成本 = 调用次数 × 单次 token × 单价。三个乘数各有各的杠杆，先砍次数，再砍 token，最后才谈换便宜模型。

你的锚：批量提取 + 结果缓存（砍次数）、统计查询直出不复述（砍 token）、按问题路由到不同档位（砍单价）。

他会问DAU 一万，一天多少钱？／怎么砍一半？

8 · 选型与部署

一句话：选型不是选最强，是选「在你客户的机房、你的预算、你的延迟要求下，够用的那个」。

四个约束：能不能出内网（私有化/信创）、一次调用能等多久（P95）、单次能花多少、要多大上下文。四个一卡，可选范围通常只剩两三个。

他会问为什么选这个模型？／国产化要求怎么满足？／换模型要返工吗？

·三个必须能一句话说清的边界

问题一句话答法为什么这么答
大模型会不会取代规则引擎？不会。规则负责可复算，模型负责可泛化；责任要签字的场景，必须留一条能复算的路。这句话同时挡住了「你是不是不懂 AI」和「你是不是过度迷信 AI」两个陷阱
RAG 会不会被长上下文取代？看三件事：资料会不会变、要不要出处、调用量多大。三个都是「是/要/大」，RAG 就还在。给判断条件，不给结论，面试官才信你是想过而不是背过
多 Agent 是不是比单 Agent 好？只有在职责能切开、边界能验收时才更好。切不开的多 Agent 是把一个 bug 变成四个 bug。反向证据你自己有：客户原来那套单体 Agentic RAG 只能查资料，不是它笨，是它没有边界
产品经理在成本题上失分，几乎都不是算错，而是没算。这一页给的是能当场写在纸上的三个公式和一张指标表。 下面的数字里，带「假设」的是示意值（换成你的实际报价），带「实测」的是你项目里已经发生的。

成本与指标：能当场算给人看

公式 → 三个杠杆 → 三层指标 → 你的真实数字

1单次调用成本

单次成本 ≈ 输入 token × 输入单价 + 输出 token × 输出单价 月成本 ≈ 日活用户 × 人均会话数 × 单会话轮次 × 单次成本 × 30 示例（假设值，替换成实际报价）： 输入 3,000 token（系统提示 + 检索到的 3 段资料 + 历史） 输出 500 token 单价 输入 ¥0.004/千token · 输出 ¥0.012/千token 单次 = 3×0.004 + 0.5×0.012 = ¥0.018 日活 1,000 × 人均 3 会话 × 每会话 4 轮 = 12,000 次/日 月成本 = 12,000 × 0.018 × 30 = ¥6,480 结论：真正决定账单的是「轮次 × 会话」，不是单价。所以产品层的降本机会最大。

2三个降本杠杆，按性价比排

杠杆怎么做省的是什么代价 / 风险
① 砍调用次数批量代替逐条、结果缓存、同一问题不重复调次数（线性省，最有效）缓存要设计失效条件；批量会拉长时延
② 砍上下文检索更准（少塞无关段落）、长文档先摘要、历史只留最近 N 轮输入 token（通常是成本大头）召回变差会伤准确率，要盯 badcase
③ 降档 / 路由简单判断走小模型、复杂才升级；能规则判的不调模型单价多一套路由逻辑和维护成本

顺序很重要：很多团队一上来就换便宜模型（③），结果准确率掉了又调回来。先把次数和上下文砍掉，往往已经省了 60%，且不掉效果。

让别人（或自己）在你讲到一半时插一句「等一下，这个为什么这么做？」。要求不回到开头，就地回答完再继续。

DAY 14
整轮模拟

打开「模拟面试」页，走完 HR / 老板 / 技术负责人三类各一轮。记下被问住的那几题，回填到「项目 Q&A」页。

如果只有 3 天

DAY A：只做项目的「一句话定位」四句（项目映射页末尾）+ 90 秒 CAD 讲法。
DAY B：T1 七个词各写一句简历句 + 成本公式手算一遍。
DAY C：录音讲两遍 + 走一轮模拟面试。

三天的目标不是学完，是「不出现硬伤」。硬伤只有两个：把 CAD 说成多模态大模型审图；把 Agent 说成会自动调工具的 chatbot。
